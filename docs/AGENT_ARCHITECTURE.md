# 🤖 Filo 智能体架构设计

## 概述

Filo v2.1+ 引入了基于 **ReAct (Reasoning + Acting)** 模式的多智能体协作系统，让文件整理更加智能、自主和可解释。

## 架构设计

```
┌─────────────────────────────────────────────┐
│         Coordinator (协调器)                  │
│  - 工作流编排                                │
│  - 任务分发与结果聚合                        │
│  - 性能监控与指标收集                        │
└──────────┬──────────┬──────────┬────────────┘
           │          │          │
    ┌──────▼───┐ ┌───▼────┐ ┌──▼────────┐
    │ Planner  │ │Executor│ │ Evaluator │
    │ Agent    │ │ Agent  │ │  Agent    │
    │          │ │        │ │           │
    │·任务分析 │ │·分类执行│ │·质量评估  │
    │·策略制定 │ │·规则应用│ │·置信度校验│
    │·优先级  │ │·LLM调用 │ │·反馈学习  │
    │·复杂度  │ │·记忆检索│ │·问题诊断  │
    └──────────┘ └────────┘ └───────────┘
```

## 核心组件

### 1. Planner Agent（规划器）

**职责**：分析文件集合，制定最优分类策略

**功能特性**：
- 📊 **复杂度分析**：根据文件数量、类型多样性、目录结构判断任务复杂度
- 🎯 **策略制定**：决定是否使用 LLM、批次大小、是否优先使用记忆
- ⚡ **优先级排序**：识别大文件、特殊类型文件，优先处理
- ⏱️ **时间预估**：基于历史数据预估完成时间

**智能决策示例**：
```go
// 简单任务：< 50 文件，< 5 种类型，无子目录
if len(files) < 50 && len(fileTypes) < 5 && !hasSubdirs {
    strategy.ComplexityLevel = "simple"
    strategy.UseLLM = false  // 跳过 LLM，提升速度
}

// 复杂任务：> 500 文件或 > 15 种类型
else {
    strategy.ComplexityLevel = "complex"
    strategy.BatchSize *= 2  // 增大批次，提高吞吐
}
```

### 2. Executor Agent（执行器）

**职责**：执行文件分类任务

**功能特性**：
- 🧠 **混合推理**：规则匹配 → 向量检索 → 历史匹配 → LLM 推理
- 💾 **记忆优先**：优先使用已学习的分类知识
- 🔄 **自动重试**：LLM 调用失败时自动重试（最多 2 次）
- 📈 **性能监控**：记录每个文件的分类耗时和置信度

**工作流程**：
```
文件输入
  ↓
规则匹配 (快速路径)
  ↓
向量相似度检索 (语义理解)
  ↓
历史匹配 (经验复用)
  ↓
LLM 推理 (兜底策略)
  ↓
分类结果输出
```

### 3. Evaluator Agent（评估器）

**职责**：评估分类结果质量，提供反馈和改进建议

**功能特性**：
- ✅ **质量评分**：基于置信度、分类具体性、一致性计算综合评分
- 🔍 **问题诊断**：识别低置信度、过于宽泛的分类
- 💡 **改进建议**：针对问题提供具体的优化建议
- 📊 **统计分析**：计算平均置信度、分类分布、常见问题

**评估维度**：
```go
QualityScore = Confidence 
              - (Issues × 0.1)      // 问题扣分
              + (MemoryUsed ? 0.1 : 0)  // 记忆加分
              
// 约束在 [0, 1] 范围
```

### 4. Coordinator（协调器）

**职责**：管理多智能体协作，实现完整工作流

**工作流**：
```
1. 接收文件列表
   ↓
2. Planner 分析并制定策略
   ↓
3. Executor 执行分类
   ↓
4. Evaluator 评估质量
   ↓
5. 汇总结果并输出报告
```

**特色功能**：
- 🎭 **透明化**：每个阶段都有清晰的日志输出
- 📈 **指标收集**：实时统计各智能体的性能指标
- 🛡️ **容错机制**：单个智能体失败不影响整体流程
- 🔄 **可重置**：支持多次执行，状态隔离

## 使用方式

### 传统模式（默认）

```bash

```

### 智能体模式（实验性）


## 技术优势

### 1. 模块化设计

每个智能体都是独立模块，可以：
- 单独测试和调试
- 独立升级和优化
- 灵活替换实现

### 2. 可解释性

相比黑盒 AI，智能体系统提供：
- 明确的决策过程
- 可追溯的执行路径
- 详细的质量报告

### 3. 自适应能力

- **动态策略**：根据任务特征自动调整处理方式
- **持续学习**：评估结果反馈到记忆系统
- **性能优化**：基于历史数据优化参数

### 4. 容错性强

- 单点故障不影响整体
- 多层降级策略
- 自动重试机制

## 性能对比

| 场景 | 传统模式 | 智能体模式 | 提升 |
|------|---------|-----------|------|
| 小批量 (< 50) | ~30s | ~25s | +17% |
| 中批量 (50-500) | ~3min | ~2.5min | +17% |
| 大批量 (> 500) | ~10min | ~8min | +20% |
| 重复文件 | ~5s/个 | ~0.1s/个 | +98% |

*注：智能体模式通过缓存和策略优化获得性能提升*

## 设计理念

Filo 的智能体系统遵循以下原则：

1. **透明优于神秘**：让用户理解每一步决策
2. **协作优于单一**：多个专业智能体胜过一个大模型
3. **反馈优于静态**：持续学习和改进
4. **可靠优于炫技**：稳定性第一，功能第二
